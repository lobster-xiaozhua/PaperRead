# PaperRead 需求规格（SPEC）

> 用户故事 + EARS 验收标准。编号规则：US-x 用户故事，AC-x 验收标准。

## 1. 导入

**US-1** 作为读者，我希望从本地文件选择 TXT/EPUB 小说导入，以便开始阅读。

- AC-1.1 当用户在书架点击「导入书籍」，系统应打开文件选择器并允许选择任意类型文件。
- AC-1.2 当用户选择非 txt/epub 扩展名的文件，系统应拒绝并提示「仅支持 TXT / EPUB」。
- AC-1.3 当目标磁盘可用空间小于文件大小 1.5 倍，系统应中止导入并提示空间不足。
- AC-1.4 当导入进行中，系统应显示进度，且界面保持可取消。
- AC-1.5 当导入的书籍与已有书籍 SHA-256 相同，系统应提示「替换 / 取消」。
- AC-1.6 当导入完成，系统应在结果页展示：标题、作者、探测编码（可手动切换）、章节数、文件大小。

## 2. 编码与章节解析

**US-2** 作为读者，我希望导入的中文小说（可能是 GBK 编码）不出现乱码，章节目录准确。

- AC-2.1 当文件带 UTF-8 / UTF-16 LE / UTF-16 BE BOM，系统应按对应编码解码。
- AC-2.2 当无 BOM 且样本段无法通过严格 UTF-8 解码（REPORT 模式），系统应回退 GB18030。
- AC-2.3 当用户在导入结果页手动切换编码，系统应使用新编码重新解析章节并刷新结果。
- AC-2.4 当 TXT 命中章节标题数 ≥ 3，系统应按正则切分章节。
- AC-2.5 当命中章节标题数 < 3，系统应依次尝试「空行+短行」启发式，再做一次行内标记扫描（`第X章` 类序号、重复书名 + `（一）` 序列），仍无命中才回退为约 3000 字符强制分段。
- AC-2.6 当文件头部存在目录页（「目录」标题 + 连续章节行），系统应跳过该区块再切分。
- AC-2.7 当 EPUB 含 DRM（META-INF/encryption.xml），系统应拒绝导入并明确提示不支持。

## 3. 书架

**US-3** 作为读者，我希望在书架看到我的书、阅读进度，并能继续上次阅读。

- AC-3.1 当书架为空，系统应展示空状态与导入引导。
- AC-3.2 书架卡片应展示：程序化封面（书名首字 + 哈希渐变）、标题、作者、进度条、百分比、最近阅读时间。
- AC-3.3 当用户点击「继续阅读」，系统应打开最近阅读书籍并恢复到保存的阅读位置。
- AC-3.4 当用户长按书籍进入多选并确认删除，系统应删除书籍文件、章节、书签及数据库记录。
- AC-3.5 书架排序应支持：最近阅读 / 书名 / 添加时间。

## 4. 阅读器

**US-4** 作为读者，我希望舒适地阅读，并能调整排版。

- AC-4.1 阅读器应以段落为单元渲染正文（LazyColumn），支持百 MB 级书籍不卡顿。
- AC-4.2 系统应支持调节：字号、行距、段距、页边距，且实时生效、自动持久化。
- AC-4.3 系统应提供 5 套预设主题：纸白 / 米黄 / 苔绿 / 黛蓝 / 墨黑。
- AC-4.4 系统应支持亮度跟随系统或手动调节、屏幕常亮、沉浸模式。
- AC-4.5 音量键翻章应默认关闭，可在设置开启。
- AC-4.6 当用户点击屏幕中央，系统应唤出/收起工具栏（上一章 / 下一章 / 目录 / 书签 / 设置）。
- AC-4.7 阅读器顶栏 / 底栏 / 正文 / 提示条应避让系统栏与刘海（三键导航、手势导航、横屏侧边导航一致），系统栏被隐藏时安全区自动归零、内容铺满屏幕；任何情况下可点击区域不得落到系统栏覆盖范围内。

## 5. 进度

**US-5** 作为读者，我希望退出后重开书籍能回到原来的位置。

- AC-5.1 当阅读位置变化，系统应在 500ms 节流内保存 ReaderPosition(chapterIndex, paragraphIndex, scrollOffset, charOffset)。
- AC-5.2 当重新打开书籍，系统应加载章节后 scrollToItem 恢复到段级 + 像素级位置。
- AC-5.3 全书进度 = (cumulativeChars + 章内 charOffset) / totalChars，章节长短不均时不应跳变。
- AC-5.4 当阅读器退到后台或退出，系统应立即写出尚未落库的位置，不得因 500ms 防抖窗口丢失最后一段滚动。
- AC-5.5 无换行文本（单行 TXT）应做长行软切分，使滚动时进度百分比实时变化，而非仅随切章跳变。

## 6. 目录与书签

**US-6** 作为读者，我希望跳转章节、收藏精彩段落。

- AC-6.1 目录弹层应列出全部章节，当前章高亮，点击跳转。
- AC-6.2 当用户添加书签，系统应记录当前位置与摘录。
- AC-6.3 书签列表应支持跳转与删除。
- AC-6.4 书架书籍菜单应提供「重新解析章节」（保守/激进两档）。

## 7. 隐私与合规

> 权限策略（2026-10-18 / 2026-10-19 用户拍板）：允许申请权限、保持**最小权限**。声明项分两组：① INTERNET——Android 无「仅局域网」权限，任何 socket（含连接局域网 IP）都必须声明它，传书 / 迁移 / 同步（第 9 节）只在同一局域网内进行，不访问公网；② 朗读前台服务三件套（第 10 节 TTS）——`FOREGROUND_SERVICE`（前台服务必须声明）、`FOREGROUND_SERVICE_MEDIA_PLAYBACK`（Android 14+ mediaPlayback 类型强制）、`POST_NOTIFICATIONS`（Android 13+ 运行时权限，朗读控制通知）。除此之外不得申请其他任何权限。

- AC-7.1 应用只声明 INTERNET 与第 10 节朗读前台服务三件套（最小权限），不得申请其他任何权限；关于页权限文案须与实际合并 Manifest 一致。
- AC-7.2 应用不得请求任何与阅读 / 局域网传输 / 朗读保活无关的权限。
- AC-7.3 应用不得访问公网：所有网络通信仅限同一局域网内的设备发现与书籍 / 状态传输（CI 以 lint / 代码审查保证）。
- AC-7.4 INTERNET 仅可用于局域网设备互传（见第 9 节），不得访问公网；README 须对权限用途显著标注。
- AC-7.5 朗读语音由系统 TextToSpeech 引擎在本机合成（优先离线引擎），不得为朗读功能发起任何网络请求。

## 8. 设置与关于

**US-8** 作为读者，我希望在设置页调整阅读偏好并查看应用信息（版本 / 隐私 / 许可 / 来源），以便不进入书籍也能配置、并了解应用背景。

- AC-8.1 当用户从书架进入「设置」，系统应展示全部阅读偏好控件（主题 / 字号 / 行距 / 段距 / 边距 / 亮度 / 常亮 / 沉浸 / 音量键）。
- AC-8.2 当用户在设置页修改任意偏好，系统应实时生效并自动持久化（与阅读器内行为一致）。
- AC-8.3 设置页与阅读器底部弹层应共用同一套控件与数据源，不得出现两套实现。
- AC-8.4 设置页应提供「关于」入口，进入后展示应用名、`versionName` 与 `versionCode`。
- AC-8.5 关于页应展示最小权限隐私承诺文案（唯一权限 INTERNET，仅用于局域网传输，不连接互联网）。
- AC-8.6 关于页应提供开源许可（Apache-2.0）查看入口，点击进入许可全文。
- AC-8.7 关于页应展示项目主页（GitHub）与反馈入口（Issue），点击以系统浏览器打开（不内置 WebView）。
- AC-8.8 关于页应展示「无第三方依赖」声明与维护者信息。
- AC-8.9 关于页任何跳转不得触发网络权限申请（与 AC-7.1 / AC-7.3 一致）。

## 9. 局域网传输

> 分发形态（2026-10-18 拍板）：传书 / 迁移 / 同步进主包，client（客户端正式版）与 dev（调试版，applicationId 后缀、可同机安装）两个 flavor 均包含本节能力。传输协议：UDP 广播发现 + 局域网 HTTP（JDK 原生 socket，不新增第三方依赖）；服务器仅绑定 WiFi 网卡地址，不监听其他接口。

**US-9** 作为读者，我希望在同一 WiFi 下把书库里的书直接传给另一台设备的纸阅，以便不依赖数据线 / 云盘完成分享。

- AC-13.1 当用户进入「传书」入口，系统应启动局域网服务并展示本机标识（设备名 + IP:端口）。
- AC-13.2 当对端应用发起发现，系统应在 3 秒内被其发现（UDP 广播发现，响应报文含协议魔数 / 版本 / 设备名 / HTTP 端口）。
- AC-13.3 当用户在书架多选书籍并选择「传书」，系统应列出已发现的在线设备；选择目标后开始传输。
- AC-13.4 传输过程中系统应展示进度（已传字节 / 总字节）与状态，且界面保持可取消。
- AC-13.5 传输完成后，接收端应将书籍落盘并走与本地导入完全相同的流水线（SHA-256 去重 / 解析 / 待确认），不得出现第二条导入逻辑。
- AC-9.6 当对端不可达或传输中断，系统应提示失败原因并清理现场（丢弃半成品文件，不影响接收端已有书籍）。
- AC-9.7 应用不得访问公网：HTTP 服务仅绑定发现阶段获取的局域网网卡地址（CI 以 lint / 代码审查保证）。

**US-10** 作为读者，我希望换机时把整库（书籍 + 进度 + 书签）一次性迁移到新设备，以便在新设备上继续阅读。

- AC-10.1 当用户选择「迁移此书库」，系统应打包全部书籍源文件与阅读状态（进度 / 书签）为单一迁移包并发送至对端。
- AC-10.2 接收端应逐本导入（复用 US-9 接收链路），导入完成后按 SHA-256 匹配回写进度与书签。
- AC-10.3 迁移中任意单本失败（DRM / 空间不足等）不得中断整体迁移，结束时系统应汇报成功 / 失败清单。
- AC-10.4 回写进度时按「最后阅读时间较新者胜」，不得用旧进度覆盖对端更新的进度。

**US-11** 作为读者，我希望两台常用设备之间的阅读进度与书签能互相同步，以便跨设备接续阅读。

- AC-11.1 当两台设备互相发现，系统应能双向交换阅读状态（每本书：SHA-256 / 进度 / 书签 / 最后阅读时间）。
- AC-11.2 同步冲突（双方均有更新）时按「最后阅读时间较新者胜」解决，并告知用户被覆盖的条目数。
- AC-11.3 仅存在于单侧的书籍 / 书签应合并到对侧，不得删除对侧独有数据。
- AC-11.4 设备标识应为随机生成并持久化的 UUID，不得使用硬件标识（MAC / IMEI / ANDROID_ID）。

## 10. TTS 语音朗读

> 范围（2026-10-19 用户拍板，ROADMAP C2）：接入**系统 TextToSpeech**（`android.speech.tts`）做离线朗读，不新增第三方依赖、不访问网络；生命周期选**后台常驻播放**（接受前台服务权限，理由见 TASKS T6）；章尾续读**默认开启、可关**。人工把关项：权限变更（前台服务三件套）、并发（合成线程回调 ↔ 主线程变更）、数据模型（朗读设置三字段）均已在 TASKS T6 备案。

**US-12** 作为读者，我希望当前章节能用系统语音朗读出来，以便做饭 / 通勤时「听书」。

- AC-12.1 阅读器应提供朗读入口（顶栏按钮），点击后从当前可见段开始朗读；再次点击可停止。
- AC-12.2 朗读过程中应支持播放 / 暂停 / 停止；系统 TTS 无 pause API，暂停以「停止并记住位置、恢复时重读当前单元」实现（听感上从当前段开头重复一句，换取状态可控）。
- AC-12.3 应支持语速（0.5 ~ 2.0）与音调（0.5 ~ 2.0）调节，改动即时生效并持久化（重启应用后保留）。
- AC-12.4 朗读时正文应按当前朗读段高亮，并随朗读进度自动滚动跟随。
- AC-12.5 单次 speak 输入受系统 TTS 上限（约 4000 字符）约束：超长段须按句末标点软切分为多个单元，逐单元合成推进，不得整表入队。
- AC-12.6 朗读中切换章节（目录 / 书签 / 进度跳转）不中断：目标章朗读单元表整体重建并从目标段续读。
- AC-12.7 章尾自动续读默认开启：一章读完自动进入下一章并从章首开播；关闭时本章读完即停止并提示「已朗读完本章」。设置为持久化开关。
- AC-12.8 锁屏 / 切后台时朗读不中断（前台服务 + mediaPlayback 类型保活），通知栏提供上一段 / 播放暂停 / 下一段 / 停止控制；系统缺少中文语音数据时明确提示原因而非静默失败。
## 11. 平板适配（C6）

**US-13** 作为读者，我希望在平板/横屏大屏上获得舒适的双页阅读与响应式布局，且不泄露任何隐私。

- AC-9.1 当 `WindowWidthSizeClass == Expanded` 且「双页跨页」开关开启，系统应渲染左右双页跨页，点按右侧翻下一屏、左侧翻上一屏、中央切换工具栏。
- AC-9.2 当窗口为 Compact/Medium，或「双页跨页」开关关闭，系统应保持单栏连续滚动（与 v1.1 行为一致）。
- AC-9.3 双页/单栏切换、旋屏后，系统应恢复到原阅读段落（沿用 ReaderPosition 段级+像素级，无跳变）。
- AC-9.4 书架网格列数应随屏宽自适应（不写死 2 列）；宽屏弹层/对话框应限宽居中。
- AC-9.5 平板适配不得新增任何权限（CI / lint 保证无 INTERNET，与 AC-7.1 / AC-7.3 一致）。

## 12. 本地备份与恢复（US-14，v2.0 / R-13）

> 形态（PRD §2.4.1 评估后拍板）：单一 zip、条目级 AES-256-GCM 可选加密、`book.txt` 与字体文件不打包（前者可从源文件重建，后者只记引用）。全程不发起任何网络请求；备份文件由用户经系统文件选择器决定存放位置。

**US-14** 作为读者，我希望把书架（书籍源文件 + 阅读进度 + 书签）备份到本机任意位置并在需要时恢复，以便换机 / 重装 / 误删后不丢阅读记录。

- AC-14.1 导出备份应包含全部书籍源文件、阅读进度与书签；`book.txt` 等派生文件不打包（恢复时由导入流水线重建）。
- AC-14.2 用户可设置口令对备份加密；口令不得写入导出文件或任何日志；加密采用条目级 AES-256-GCM，密钥由 PBKDF2-HMAC-SHA256（≥ 100,000 次迭代）派生。
- AC-14.3 恢复时应校验备份版本；高于当前应用支持的版本须明确拒绝并提示「备份版本过新」。
- AC-14.4 恢复应逐本走与本地导入 / 传书 / 迁移完全相同的导入流水线；SHA-256 命中书架的书籍跳过导入。
- AC-14.5 单本恢复失败（条目损坏 / 源文件缺失 / 解析失败）不得中断整体恢复，结束时汇报成功与失败明细。
- AC-14.6 进度与书签回写按「最后阅读时间较新者胜」，不得用旧进度覆盖本地更新的进度。
- AC-14.7 口令错误应提示「口令错误」并可原地重试，不得泛化为「文件损坏」。
- AC-14.8 恢复前应可预览备份内容摘要（版本 / 创建时间 / 书籍数 / 进度数 / 书签数 / 书目 / 字体引用）。
- AC-14.9 备份不包含字体文件，仅记录字体引用；恢复时字体缺失应回退默认字体并在结果中提示。
- AC-14.10 备份与恢复全程不得发起任何网络请求（CI `check-network-behavior.sh` 静态断言）。

## 13. 全书搜索（US-15，v2.0 / R-14）

> 范围（决策 D4）：v2.0 **仅当前书**，不建索引、不整本载入内存、零网络；
> v2.1 的书架级全局搜索实现同一 `BookSearchSource` 接口与 `SearchHit` 契约，
> UI / ViewModel 协议不变。契约定义见 `:core:domain` 的
> `io.github.lunalight.paperread.domain.search`（实现 `:core:data` 的
> `CurrentBookSearchSource`）。

**US-15** 作为读者，我希望在当前书籍内按关键词搜索并跳转到命中段落，以便在长书中快速找回内容。

- AC-15.1 阅读器应提供「本书搜索」入口（工具栏或目录弹层）。
- AC-15.2 当用户输入 ≥ 2 个字符的关键词并触发搜索，系统应扫描当前书籍并在结果列表展示命中条目（章节名 + 段落摘要 + 命中次数）。
- AC-15.3 当用户点击搜索结果，系统应跳转到对应章节并滚动定位到命中段落，命中词应高亮。
- AC-15.4 搜索应为增量流式：先命中的章节先展示，不得等全书扫描完成才输出首批结果。
- AC-15.5 搜索应可取消：取消后应回到发起搜索前的阅读位置，且不得改动已保存进度。
- AC-15.6 性能边界（中端机 API 34）：100MB 级 TXT 从输入完成到首批结果 ≤ 5s；结果点击到段落定位完成 ≤ 1s；取消响应 ≤ 500ms。搜索应为流式逐章扫描，不得为建索引将全书载入内存（守住 200MB 书 PSS < 100MB 红线）。
- AC-15.7 搜索无命中应提示「未找到相关内容」。
- AC-15.8 搜索应经 `BookSearchSource` 接口与 `SearchHit` 数据契约实现；v2.1 书架级搜索实现同一接口时，不得改动 UI/VM 层协议。
- AC-15.9 搜索仅在本机内存/磁盘进行，不得发起网络请求、不得将书籍内容传出设备。
- AC-15.10 搜索进行中离开阅读器或页面销毁时，系统应取消在途扫描，不得泄漏协程或文件句柄。

## 14. 书签备注与按章分组（US-17，v2.0 / R-18）

> 数据层：备注（`note`）与备注更新时间（`updatedAt`）随 schema v2 落地（T-006 / R-06），
> v1→v2 AutoMigration 已由 CI 迁移测试守住（`fallbackToDestructiveMigration` 保持禁用）。

**US-17** 作为读者，我希望给书签写备注并按章整理，以便长书积累后快速找回精彩段落。

- AC-17.1 当用户添加书签，系统应允许输入备注（可空，≤ 500 字）。
- AC-17.2 书签列表应按章分组展示，条目应显示备注摘要与位置（章名 + 段序号）。
- AC-17.3 当用户编辑已有书签，系统应支持修改备注；书签跳转与删除行为不得回归（AC-6.2/6.3）。
- AC-17.4 书签模型扩展（备注/更新时间等字段）必须带 Room 迁移（v1→v2，新增列带默认值），且迁移测试纳入 CI（门槛 G6）；`fallbackToDestructiveMigration` 保持禁用。
- AC-17.5 当同步/迁移快照携带新字段且对端为旧版本（v1.2），旧版反序列化应忽略未知字段并正常完成合并，不得整体失败。
- AC-17.6 当新版本接收旧版本书签（无备注字段），系统应以默认值接纳并正常参与合并，不得崩溃或丢弃书签。
- AC-17.7 书签合并去重键应保持「章节+段落+字符偏移」不变；备注冲突按「更新时间较新者胜」，不得因备注差异产生重复书签（书签合并「只增不删」语义不变，AC-11.3）。
- AC-17.8 所有快照解析点（迁移包/同步包）应显式启用「忽略未知字段」序列化配置，并有新旧字段互通的单测覆盖。

## 15. 自定义字体（US-16，v2.0 / R-17）

> 数据层：字体文件落 `filesDir/fonts/<id>.<ext>`，元数据落独立 DataStore（`custom_fonts`）；
> 阅读偏好新增 `customFontId`（默认 null = 内置字族）。解析器为零依赖字节解析
> （`reader/font/TtfMetadata.kt`），不引入任何字体 / 第三方库。

**US-16** 作为读者，我希望导入自己喜欢的字体用于正文，以便长时间阅读时更舒适。

- AC-16.1 当用户进入阅读设置，系统应提供「导入字体文件」入口，经系统文件选择器（SAF）选取本机字体。
- AC-16.2 系统应仅接受 TTF / OTF（含字体集合 ttcf）容器，按文件头魔数（`0x00010000` / `OTTO` / `true` / `ttcf`）校验；不合法的文件必须拒绝并给出明确提示，不得导入。
- AC-16.3 字体列表应显示三项信息：字体显示名（取自字体的 `name` 表；取不到时回退来源文件名）、来源文件名、删除按钮。
- AC-16.4 当用户选用某份自定义字体，正文（含连续滚动与翻页两条渲染路径）应立即以该字体渲染，选择结果持久化并在重启后保持。
- AC-16.5 当用户删除正在使用的字体，系统应清除该引用、正文回退默认字体，并在界面上明确提示「已回退」。
- AC-16.6 当已选字体的文件缺失、被删除、内容损坏或解析失败，正文必须**静默回退**默认字体，不得崩溃、不得出现空白正文。
- AC-16.7 单个字体文件应有大小上限（20MB）；超限拒绝并提示，防止误选超大文件占满磁盘。
- AC-16.8 字体功能必须全程离线：不得下载字体、不得访问网络（零网络承诺不变，`check-network-behavior.sh` 保持绿）。

## 16. 新手引导（US-18，v2.0 / R-15）

> 状态标记落独立 DataStore（`app_prefs`），与 `reader_settings` 分开；
> 「是否老用户」由装配层注入判据（`AppContainer.hasLegacyUsage()`）。

**US-18** 作为新用户，我希望第一次打开时被简要告知数据在哪、书怎么进来、听书需要什么，以便不靠猜就能用起来。

- AC-18.1 首次启动且**无任何使用痕迹**时才展示引导；升级安装（已有阅读设置或书架非空）不属于首次，不得展示。
- AC-18.2 引导应包含三屏且各讲一件事：① 数据仅存本机、不联网；② 导入 TXT/EPUB 与局域网传书 / 换机迁移；③ 听书依赖系统 TTS 中文语音包（缺失时按 AC-12.8 的话术提示）。
- AC-18.3 三屏应支持左右滑动切换，提供「跳过」，末屏按钮为「开始使用」；完成或跳过后不再自动展示。
- AC-18.4 设置页应提供「重新查看引导」入口，可随时重看（且不影响已记录的「已看过」状态）。
- AC-18.5 空书架应展示空态：一句话说明 + 主行动「导入书籍」+ 次行动「局域网传书」；书架有书后空态自动消失。
- AC-18.6 引导与空态的全部文案必须来自 `strings.xml`，不得硬编码在 Compose 代码里。

## 17. 反馈与诊断导出（US-19，v2.0 / R-16）

> 数据边界：诊断包只含应用版本、设备型号、错误堆栈、导入失败摘要；
> **不含**书籍正文、书源、书签内容、书名或个人信息。零网络：包由用户自行分享。
> 注：本节早期版本曾标注「R-21」，与发行物料需求（US-21 / R-21）冲突，
> 已移除该标注；US-19 对应的需求编号为 R-16，已按 PRD 需求池核对回填（见 §21 追溯表）。

**US-19** 作为遇到问题的用户，我希望一键导出诊断信息附在反馈里，以便维护者能定位问题而不必我描述堆栈。

- AC-19.1 关于页应提供「导出诊断信息」入口，与 GitHub Issue 入口并列。
- AC-19.2 导出前应先展示摘要（应用版本 / 设备 / 崩溃条数 / 导入失败条数 / 数据边界声明），用户确认后才选择保存位置并落盘。
- AC-19.3 诊断包（zip）应包含：`summary.txt`（版本 / 设备 / API / 崩溃条数 / 最近导入失败）、`crashes/*.log`（崩溃日志）、`import-errors.json`（最近导入失败）。
- AC-19.4 崩溃日志环形保留 10 份、导入失败环形保留 5 条，超限淘汰最旧；崩溃日志须含时间、应用版本、设备型号与 API 级别、线程、异常与堆栈。
- AC-19.5 诊断包不得包含书籍正文、书源、书签内容或路径中的书名；崩溃堆栈里的私有目录路径、书籍目录名与 UUID 必须脱敏。
- AC-19.6 导出取消或失败时不得在用户所选位置留下半成品；只清理由本次 `CreateDocument` 新建的目标文档（用户既有文件不得误删）。
- AC-19.7 崩溃钩子必须链式调用系统原处理器（记录后照常转发），不得吞掉崩溃导致系统不显示 FC 对话框；反馈入口仍以系统浏览器打开 GitHub Issue，不内置 WebView。

## 18. 隐私可验证化（US-20，v2.0，承接第 0 阶段 R-02 / G2）

> 实现载体：`ui/about/PrivacyScreen.kt` + `strings.xml` 的 `privacy_*` 资源 +
> `scripts/check-network-behavior.sh` + `docs/NETWORK_AUDIT.md`（T-009）。

**US-20** 作为注重隐私的用户，我希望应用的隐私承诺不止是宣传语，而是逐项可验证的，以便放心安装使用。

- AC-20.1 当用户首次使用朗读且通知权限未授权，系统应先场景化说明用途、经确认后再申请 `POST_NOTIFICATIONS`，不得未告知即申请（先告知、再申请、后朗读）。
- AC-20.2 应用不得在冷启动时批量申请运行时权限；运行时权限申请必须发生在具体功能首次需要时。
- AC-20.3 关于页应提供「隐私说明」一页，列明全部权限及逐项用途、网络行为边界与备份加密 / 诊断导出的数据边界。
- AC-20.4 隐私说明页的权限清单应与实际合并 Manifest 逐项一致（测试断言；Manifest 增删权限而不同步本清单即测试失败）。口径澄清：合并 Manifest 实测**应用声明为 4 项**（INTERNET / FOREGROUND_SERVICE / FOREGROUND_SERVICE_MEDIA_PLAYBACK / POST_NOTIFICATIONS）；部分工具报告的「第 5 项」`DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` 系 androidx.core 自动注入的 signature 级权限，非应用声明，不计入本清单。
- AC-20.5 「不访问公网」承诺应可验证：CI 对全部运行时源码做静态断言（无三方网络 / 统计 SDK、URL 字面量白名单、网络 API 收敛在局域网传输代码内），审计口径公开在 `docs/NETWORK_AUDIT.md`。
- AC-20.6 当朗读起播时通知权限已被用户撤销（探测结果翻转为已撤），系统应明确提示并引导重新授权，不得静默失败。

## 19. 发行与文案工程化（US-21，v2.0 / R-21）

**US-21** 作为潜在用户与打包者（F-Droid 打包员 / 关注隐私的读者），我希望仓库提供规范完整的发行物料与可信的文案管理，以便了解并安装这个应用。

- AC-21.1 仓库应提供 F-Droid 元数据（`fastlane/metadata/android/<locale>/`：名称 / 简述 / 详述 / 许可 / 源码 / 议题跟踪 / 更新日志），字段符合 F-Droid 官方规范（title ≤ 30 字符、short ≤ 80、full ≤ 4000、changelogs/<versionCode>.txt ≤ 500）。
- AC-21.2 仓库应提供独立隐私政策文本（`PRIVACY.md`，公开可访问 URL），内容与应用内隐私说明页一致，并明确「无账号 / 无云同步 / 无遥测 / 局域网通信不访问公网」。
- AC-21.3 仓库应提供 Release 说明模板（`docs/release-notes-template.md`：新增 / 变更 / 修复 / 已知问题 / 升级注意），自首个 v2.0 Release 起使用；升级注意段必须显著标注传输协议与 v1.2 不兼容（R-01 的 breaking change）。
- AC-21.4 全部用户可见 UI 文案应资源化进 `strings.xml`，CI 硬编码中文文案门禁（`strings-check` 作业）保持绿。

- AC-21.6 README 应更新发行渠道（GitHub Releases + F-Droid）与安装指引（client 正式版 / dev 调试版的区分），并明确不上架 Google Play 与国内应用商店（决策 D1）。
- AC-21.7 `CHANGELOG.md` 应与 Release 说明联动更新（同构五段）；`versionName` 按语义化版本、`versionCode` 按既有节奏（+1）递增，F-Droid 更新日志随 versionCode 同步。
