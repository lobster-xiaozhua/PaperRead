# Release 说明模板

> 自 v2.0.0 起使用（AC-21.3）：每次发版的 GitHub Release 说明按本模板撰写，
> 与 `CHANGELOG.md` 对应版本条目联动——CHANGELOG 是追加式全量记录，Release
> 说明是面向用户的当次摘要；两者五段结构保持一致，细节可以互相引用而不重复。
> 模板中的 `【】` 为占位符，发布时替换；不适用的段落整段删除（不要留空段）。

---

## 新增

- 【功能一句话】（US-xx / T-xxx）：【两三句面向用户的说明，说清「能得到什么」而非「改了哪些类」】

## 变更

- 【行为变化一句话】：【旧行为 → 新行为，以及为什么要改；若影响用户操作习惯，在「升级注意」重复一遍】

## 修复

- 【缺陷一句话】（F-xx / P3-x）：【症状 + 根因一句话 + 修法一句话】

## 已知问题

- 【问题一句话】：【触发条件与规避方式；无则写「无」并删除本段】

## 升级注意

> **Breaking**：【不兼容变更显著标注，逐条列出；无 Breaking 时写「本次升级无破坏性变更」并删除警示块】

- 【Breaking】**传输协议升级至 v2，与 v1（v1.2 及更早）设备不互通**：v2.0 起局域网
  传书 / 换机迁移 / 进度同步启用 v2 协议并要求配对鉴权（v1 报文一律拒绝，新旧版本
  设备无法互相发现）。升级本版本后，需要与你对传的两台设备**都要升级到 v2.0**，
  并在每次开放传书时重新完成配对（配对码当面展示输入，不经网络传输）。
  （示例条目，继承自 v2.0.0 CHANGELOG 的 breaking 描述——后续版本按实际 breaking
  改写，不要原样照抄。）
- 【版本门控 / 数据格式变化】：【如备份格式、迁移包、数据库 schema 有版本门控，说明旧版本数据的兼容行为】

---

## 发布清单（模板之外的固定动作）

1. 更新 `app/build.gradle.kts` 的 `versionName` / `versionCode`（versionCode 按既有节奏 +1）
2. `CHANGELOG.md` 新增对应条目（把「未发布」改为发布日期，更新底部链接区间）
3. `fastlane/metadata/android/zh-CN/changelogs/<新 versionCode>.txt`（≤ 500 字符，面向 F-Droid 用户的一句话摘要 + breaking 提示）
4. 按「升级注意」段核对 `PRIVACY.md`：权限清单 / 网络行为有变化必须同步
5. 打标签并推送；在 GitHub Releases 基于该 tag 创建 Release 并附上 client 正式版 APK（dev 调试版按需附加）
6. 真机走查：`docs/DEVICE_CHECKLIST.md`（含 §9 TalkBack 与 200% 字号）
